# RaspberryPi Multispectral Imaging

Raspberry Pi 5 + USB 카메라 3대용 로컬 브라우저 프로그램.
현재 기능: 3채널 미리보기, 동시 녹화 시작/중지, 카메라별 AVI/시간 CSV 저장,
완료된 세션의 시간 기반 RGB 합성, 카메라별 4점 원근 정합, 회전·배율·X/Y 이동 설정 저장.
필터 장착 전에는 파장별 다분광 측정이 아닌 기능 개발용입니다.

## Raspberry Pi 설치

64비트 Raspberry Pi OS에서 저장소 디렉터리로 이동한 후 실행합니다.
OS 패키지의 OpenCV를 사용하므로 Pi에서 pip로 OpenCV를 빌드할 필요가 없습니다.

```bash
sudo apt update
sudo apt install -y python3-venv python3-opencv python3-numpy python3-flask v4l-utils ffmpeg
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
python -c "import cv2, numpy, flask; print(cv2.__version__)"
python app.py
```

라즈베리파이의 브라우저에서 `http://127.0.0.1:8000`을 엽니다.
다른 촬영 프로그램은 먼저 종료하세요. 서버 종료는 터미널의 Ctrl+C입니다.
서버는 로컬 접속만 허용하며 외부 인터넷에 노출하지 마세요.
다른 PC에서는 SSH 터널 `ssh -L 8000:127.0.0.1:8000 jonginkim@<Pi주소>`을
연결한 다음 해당 PC의 브라우저에서 같은 주소를 사용할 수 있습니다.

### 카메라 연결

`app.py`의 `DEVICES`는 다음 포트로 설정되어 있습니다.
USB 포트를 바꾼 경우 `ls -l /dev/v4l/by-path/`로 확인해 수정하세요.

| 이름 | /dev/v4l/by-path/ 아래 경로 |
|---|---|
| cam1 | platform-xhci-hcd.1-usb-0:2:1.0-video-index0 |
| cam2 | platform-xhci-hcd.0-usb-0:2:1.0-video-index0 |
| cam3 | platform-xhci-hcd.1-usb-0:1:1.0-video-index0 |

입력은 YUYV 640×480, 요청 프레임률 30fps입니다.
실행 시 수동 노출(`auto_exposure=1`, `exposure_time_absolute=4500`)을 적용합니다.
종료 후에도 설정은 남습니다. 필요하면 각 장치에
`v4l2-ctl -d /dev/video0 --set-ctrl=auto_exposure=3`처럼 자동 노출을 복원하세요.
권한 오류는 `id`로 video 그룹 가입 여부를 확인하세요. 필요한 경우
`sudo usermod -aG video "$USER"` 후 로그아웃/로그인하세요.
카메라가 끊기면 녹화가 종료되며, 연결을 복구한 후 프로그램을 재시작하세요.

## 실시간 합성 미리보기

앱 실행 후 **실시간 합성 미리보기**에서 계산 폭 320, 목표 5fps로 시작하세요.
출력은 640×480이며 축소 영상에서 구한 국소 흐름을 원본 크기로 확대해 적용합니다.
계산 폭 320은 320×240, 480은 480×360, 640은 640×480에서 국소 정합을 계산한다는 뜻입니다.
목표 속도는 5/10/15/20/30fps를 선택할 수 있습니다. 320에서 15→20→30 순으로 올리고
실제 처리 fps와 정합 정확도를 비교하세요. 목표 속도는 상한이며 달성을 보장하지 않습니다.
목표 15/20/30fps의 프레임당 시간 예산은 약 67/50/33ms입니다. 전역 정합 갱신과
일관성 검사 시에는 더 오래 걸릴 수 있습니다. 입력 카메라의 실제 프레임률도 상한이 됩니다.
현재 RGB 배치, 4점 정합과 미세 조정값을 초기값으로 사용합니다.
전역 ORB 정합은 약 1초마다 갱신하며, 실패하면 기존 보정값을 유지하고 상태를 표시합니다.
전역 정합을 한 번도 확인하지 못했다면 초기값으로 처리 중임을 표시합니다.

- 처리 fps: 실제 출력 생성 간격의 이동 평균입니다. 목표값을 보장하지 않습니다.
- 처리 시간: 정합·국소 보정·JPEG 생성에 걸린 시간입니다.
- 호스트 수신 후 경과: 출력에 사용한 가장 오래된 카메라 프레임의 수신 시각부터 현재까지의 시간입니다.
  센서 노출부터의 지연이나 브라우저 표시 지연을 포함한 종단 지연은 아닙니다.
- 카메라 시간 차: 선택한 세 프레임의 호스트 수신 시각 차이입니다. 하드웨어 동기화가 아닙니다.
- cam1 처리 생략: 입력 중 실시간 처리에 사용하지 않은 프레임 수입니다. 원본 녹화 드롭 수가 아닙니다.
- 왕복 일관성: 매 5번째 처리 프레임에서 검사합니다. 마지막 검사 프레임 번호를 함께 표시합니다.
  중간 프레임의 검사값이 아니며, 일관성 통과가 정확한 대응을 보장하지 않습니다.

카메라별 최근 8프레임 중 공통 시각에 가까운 프레임을 선택하며, 처리 대기열은 만들지 않습니다.
처리가 늦으면 오래된 입력은 생략합니다. 카메라 수신이 1초 이상 갱신되지 않으면 결과 갱신을 멈추고 경고합니다.
실시간 합성은 원본 녹화와 별도 스레드에서 실행합니다. 녹화 시작/중지는 기존 버튼을 사용하세요.
CPU와 디스크를 공유하므로 동시에 실행하면 두 기능의 성능이 떨어질 수 있습니다.
실시간 합성 결과 저장은 아직 지원하지 않습니다.
후처리 합성을 실행하려면 실시간 합성을 먼저 중지하세요. 둘을 동시에 실행하지 않습니다.

실시간은 미래 프레임을 기다리지 않으며, 후처리의 중앙 시간축 평활화는 적용하지 않습니다.
따라서 만족한 `_smooth_local.avi`와 정합·안정성이 동일하지 않을 수 있습니다.
국소 DIS는 FAST 설정으로 계산하며 화면 전체 이동 안정화는 적용하지 않습니다.
설정을 변경한 뒤에는 중지/재시작해야 반영됩니다.

Pi에서 처리 속도가 부족하면 목표 5fps·계산 폭 320부터 확인하세요.
정합 세부가 부족하면 폭 480/640으로 높이되 실제 fps와 처리 시간을 비교하세요.
OpenCV 스레드는 기본 2개입니다. `python app.py --cv-threads 1` 등으로 비교할 수 있습니다.
이 숫자는 카메라 캡처 스레드 수와는 별개입니다.
클라우드 가상 카메라와 업로드 영상 재생으로 동작을 검증했으며, Pi 5의 실제 처리 속도는 별도 측정해야 합니다.

## 실시간 단계별 성능 측정

1. 계산 폭 320, 목표 30fps로 실시간 합성을 시작합니다. 목표 fps 대기는 처리 시간에서 제외됩니다.
2. 첫 측정은 원본 녹화를 끈 상태로 약 60초 진행합니다.
3. 실시간 합성을 중지하고 **계측 결과 JSON 다운로드**를 눌러 저장합니다.
4. 필요하면 원본 녹화를 켠 상태로 같은 설정에서 반복합니다. 새 측정은 통계를 초기화하므로
   이전 JSON을 먼저 보관하세요. 원본 녹화 자체는 실시간 중지 버튼으로 종료되지 않습니다.

화면의 단계별 평균은 첫 5개 출력(예열)을 제외한 전체 프레임 기준입니다.
실행 시 평균은 해당 단계가 실행된 프레임만 계산합니다. 예를 들어 전역 정합은 약 1초마다,
역방향 DIS 검사는 5개 출력마다 실행되므로 전체 평균만 보면 비용이 작게 보일 수 있습니다.
P95는 최근 최대 300개 측정 출력으로 계산하며 전체 구간의 P95와 다릅니다.
전체 구간 평균·최댓값과 일반/전역 갱신/일관성 검사/동시 실행 프레임의 집계를 함께 저장합니다.
녹화와 겹친 출력 수 및 별도 그룹도 기록합니다.

측정 항목: 프레임 선택(녹화 잠금 대기 포함), 회색조, 전역 정합, 전역 영상 변환,
축소·CLAHE, DIS 정방향, DIS 역방향, 흐름 확대·국소 변형, 일관성 계산, RGB 합성,
JPEG 인코딩, 기타 처리, 전체 처리입니다. 기타 처리는 순수 Python 비용으로 해석하면 안 됩니다.
각 항목은 벽시계 경과 시간이므로 다른 스레드와 CPU를 공유하며 기다린 시간도 포함될 수 있습니다.
카메라 노출/입력 드라이버 처리, 목표 속도 대기, 실제 소켓 전송, 브라우저 표시 지연은
이 표에 포함하지 않습니다. JPEG 인코딩이 빠르다고 브라우저 전송도 빠르다는 뜻은 아닙니다.

중지하면 `captures/profiles/live_날짜_시각.json`에 자동 저장합니다.
다운로드는 라즈베리파이 앱의 `/api/live/profile?download=1`에서 현재/직전 실행 결과를 받습니다.
실행 중 다운로드는 그 시점의 누적 통계입니다. 파일에는 카메라 영상이나 자격증명을 담지 않습니다.
JSON을 공유하면 실제 Pi 병목을 보고 C++ 전환, 메모리 복사 축소, 알고리즘 설정 중
어느 접근이 필요한지 판단할 수 있습니다. 클라우드 측정 결과를 Pi 성능으로 간주하지 마세요.

## 사용 순서

1. 세 미리보기와 프레임률을 확인합니다.
2. 녹화 시작 → 녹화 중지. 먼저 짧은 10초 촬영으로 저장 성능을 확인하세요.
3. 완료된 세션을 선택하고 RGB 채널에 서로 다른 카메라를 배치합니다.
4. 정합 미리보기의 시간 슬라이더로 정지된 평면 대상이 보이는 장면을 고릅니다.
   아래 원본 cam1·cam2·cam3에서 같은 평면의 특징점 4개를 동일한 순서로 클릭합니다.
   예: 종이의 왼쪽 위 → 오른쪽 위 → 오른쪽 아래 → 왼쪽 아래.
   마우스를 올리면 8배 돋보기·픽셀 격자·중심 십자선·원본 좌표가 표시됩니다.
   클릭은 십자선 중앙의 정수 픽셀을 선택합니다. 클릭 없이 마우스를 영상에 올려
   대략적인 위치를 잡은 뒤 방향키로 1픽셀씩 이동하고 Enter로 점을 저장할 수 있습니다.
   각 영상의 키보드 선택 시작 버튼 또는 Tab으로 영상에 포커스를 두어도 됩니다.
   Enter는 점 목록에 저장하며, 파일 보존은 합성 영상 저장 시 이루어집니다.
   점은 넓게 분포시키고 일직선·중복을 피하세요. 점 완성 시 원근 변환을 적용합니다.
   cam1이 기준이며 cam2·cam3의 배율·회전·원근 차이를 함께 보정합니다.
   필요하면 추가 회전·배율·X/Y로 미세 조정하세요. 원근 보정 → 회전/배율 → 이동 순서입니다.
   잘못 클릭한 점은 마지막 점 취소 또는 점 초기화로 다시 선택합니다.
5. 정렬이 맞으면 합성 영상 저장을 누릅니다.
6. `captures/<세션>/composite.avi`를 VLC 등에서 확인합니다.
   합성은 동기 처리이므로 완료까지 기다리세요. 긴 영상은 시간이 걸립니다.

세션마다 `cam1~3.avi`(MJPEG), `cam1~3.csv`, `session.json`을 저장합니다.
합성 후 `alignment.json`과 `composite.avi`가 추가됩니다.
재합성은 이 두 파일을 덮어씁니다. 중요한 결과는 별도 복사하세요.
합성 완료 시 대응점과 미세 조정값을 alignment.json에 보존하며, 세션을 다시 선택하면 복원합니다.
합성을 저장하기 전의 편집값은 페이지 새로고침 시 사라집니다.
원근 변환의 결과 중 원본 밖 영역은 검은색으로 표시됩니다.
저장 위치는 `python app.py --output /원하는/디렉터리`로 변경합니다.
저장 공간을 확인하세요. MJPEG 인코딩과 디스크 성능은 실제 Pi에서 검증해야 합니다.

## 필터 없는 영상의 자동 정합 검증

1. 세 카메라가 같은 평평한 인쇄물·포스터를 보도록 촬영합니다. 무늬가 없는 벽,
   반복 격자만 있는 장면, 흔들린 장면, 움직이는 물체는 피하세요.
2. 완료 세션을 선택하고 시간 슬라이더로 선명한 정지 장면을 고릅니다.
3. **선택 장면 자동 정합**을 누릅니다. ORB 특징점 매칭과 RANSAC으로
   cam2·cam3을 cam1에 맞추는 두 원근 변환을 계산합니다.
4. 성공하면 두 변환을 함께 적용하고 미세 조정값은 중립값으로 초기화합니다.
   특징점 수·유효점 비율·중앙 재투영 오차·특징점 분포를 표시합니다.
   점이 적거나 한곳에 몰리거나 오차가 큰 결과는 거부하며 기존 설정을 유지합니다.
5. 중첩 윤곽을 확인하고 다른 시간에서도 맞는지 슬라이더로 검사하세요.
   수치가 좋아도 특정 평면만 맞거나 반복 무늬를 잘못 맞출 수 있습니다.
   필요하면 **자동 정합 전 설정 복원**으로 직전 설정을 되돌립니다.
6. 합성 영상 저장을 누르면 계산한 제어점과 설정이 alignment.json에 저장됩니다.

자동 정합 후 원본 위 4점은 실제 매칭 특징점이 아니라 계산한 변환을 표현하는
제어점입니다. 수동 점 선택으로 다시 수정할 수 있습니다.
이 단계는 **선택한 한 프레임에서 구한 고정 변환**을 검증합니다.
이동 중 대상 거리·평면이 변하면 아래 프레임별 자동 정합 모드를 사용할 수 있습니다.
현재 신뢰도 수치는 추정에 사용된 대응점에 대한 지표이며 장면 전체 정확도를 보장하지 않습니다.
필터 장착 후 파장별 외형 차이에서는 ORB가 실패할 수 있어 별도 검증이 필요합니다.

## 프레임별 자동 정합 (저장 영상)

1. 먼저 짧은 5~10초 영상으로 확인합니다. 필요하면 수동 4점 정합이나
   선택 장면 자동 정합으로 초기 보정값을 준비합니다.
2. **프레임별 자동 정합 (저장 영상 후처리)**을 체크하고 합성 영상 저장을 누릅니다.
3. 진행 프레임 수, 자동 정합 성공 수, 대체값 사용 수를 화면에서 확인합니다.
   Raspberry Pi에서 매 프레임 특징점 검출은 오래 걸릴 수 있습니다.
4. 결과 `composite_dynamic.avi`를 확인합니다. 기존 `composite.avi`는 보존합니다.
   같은 모드를 재실행하면 해당 모드 결과와 진단 파일을 덮어씁니다.

각 출력 시점에서 시간상 가장 가까운 세 원본 프레임을 고르고 ORB/RANSAC으로
cam2·cam3을 cam1에 맞춥니다. 기본값은 매 프레임 ORB 재검출 방식입니다.
실험 옵션인 특징점 추적은 첫 정합의 유효 대응점을 양쪽 영상에서 LK 광학 흐름으로
추적하며 정방향·역방향 추적 오차와 RANSAC 품질을 검사합니다. 추적 실패 또는 30프레임마다
ORB로 다시 검출합니다. 두 카메라 모두 품질 검사를 통과한 경우에만
새 변환을 함께 적용합니다. 안정화 강도에 따라 투영된 모서리 위치를 저역통과 필터로 처리합니다.

| 모드 | 현재 추정 반영 | 미세 변화 유지 범위 |
|---|---:|---:|
| 강하게 | 15% | 1.0px |
| 균형 (기본) | 30% | 0.7px |
| 빠르게 | 60% | 0.3px |

유지 범위 이내 변화는 직전 값을 그대로 사용합니다. 큰 변화(모서리 이동 30px 초과)는
연속 3회 유사한 추정(모서리 차이 8px 미만)이 확인될 때까지 보류합니다.
확인된 급변은 새 값으로 재획득하므로 그 순간 화면이 바뀔 수 있습니다.
빠른 실제 움직임도 급변으로 판단할 수 있으며, 강한 안정화는 추종 지연과 정합 오차를
늘릴 수 있습니다. 먼저 균형으로 비교하고 떨림이 크면 강하게, 추종이 늦으면 빠르게를 선택하세요.
이 기능은 정합 변환의 떨림을 줄이며 cam1 영상 자체의 흔들림을 제거하지 않습니다.
회전·배율 미세 조정과 X/Y 이동은 자동 변환 위에 적용되므로 특별한 목적이 없다면
미세 조정을 0도·1배·0픽셀로 두세요. 첫 성공 전 대체값은 현재 4점 설정과 미세 조정입니다.

정합 실패 시 직전 유효값을 유지합니다. 한 번도 성공하지 못했다면 초기 설정을 사용하며,
초기 설정도 없다면 항등 변환(정합 없음)입니다. 대체값을 사용한 프레임도 영상에 포함되므로
**파일 생성 완료가 모든 프레임의 정합 성공을 뜻하지 않습니다.**
전체 실패 시 결과에 경고를 표시합니다. 장기간 실패하면 영상이 계속 어긋날 수 있습니다.

- `registration_dynamic.jsonl`: 프레임 번호, 원본 시간, 상태(`estimated`,
  `fallback_previous`, `fallback_initial`), 실패 이유, 품질 지표, 적용 변환 행렬.
  `method`는 특징점 추적(`optical_flow`) 또는 재검출(`orb_reacquire`)을 나타냅니다.
  `filter_state`는 초기 적용·미세 변화 유지·평활화·급변 보류·재획득 상태를 기록합니다.
- `registration_dynamic_summary.json`: 완료 여부와 성공/대체값 사용 집계.
  중단되면 `completed: false`가 남습니다. 중단된 영상은 완성본으로 사용하지 마세요.
- `alignment.json`: 초기 보정값과 프레임별 모드 선택을 보존합니다.

중첩 미리보기는 현재 고정 보정값을 보여주며 동적 결과는 저장된 영상을 확인해야 합니다.
이 기능은 후처리이며 실시간 합성은 아닙니다. 시간 차이, 렌즈 왜곡, 깊이별 시차를
해결하지 않으며, 하나의 평면이 지배적인 장면에서 먼저 검증하세요.

## 가까운 물체와 배경의 국소 정합 (시험 기능)

단일 원근 변환은 깊이가 다른 손과 배경을 동시에 맞추지 못합니다.
**국소 정합 — 가까운 물체/배경의 위치별 차이 보정**은 전역 정합 후 DIS dense optical flow로
cam1과 다른 카메라 사이의 픽셀별 잔여 대응을 계산합니다. 대상 영역을 지정할 필요는 없습니다.

1. 프레임별 자동 정합, ORB, 시간축 떨림 완화 31프레임을 선택합니다.
2. 국소 정합을 켭니다. 전체 화면 흔들림 보정은 끕니다.
3. 짧은 영상으로 합성하고 손의 윤곽과 배경의 변형을 함께 비교합니다.

출력 예: `composite_dynamic_smooth_local.avi`.
동일 이름에 `_validity`가 붙은 영상은 양방향 흐름 일관성 검사입니다.
흰색은 두 카메라 모두 왕복 오차 1.5px 미만·이동 60px 미만·영상 내부·암부 제외 조건을
통과한 곳이며, 검은색은 검사에서 통과하지 못한 곳입니다.
**흰색도 정확한 대응의 정답을 보장하지 않습니다.** 특히 반복 무늬에서는 오대응이 가능합니다.
검사 좌표를 유지하기 위해 전체 이동 보정과 국소 정합은 동시에 사용할 수 없습니다.

출력 영상은 유한한 60px 이내 흐름을 이용한 근사 변형을 포함합니다.
검은 영역이 합성에서 제거되는 것은 아니므로 자연스럽게 보이는 색을 정합 성공으로 해석하면 안 됩니다.
60px 이상/비정상 흐름은 전역 결과로 대체합니다.
가림으로 한 카메라에만 보이는 영역, 무늬 없는 어두운 손, 반사체는 복원이 불가능하거나 부정확할 수 있습니다.
보정은 물체의 모양을 변형할 수 있고 실제 영상의 프레임 간 일관성도 확인해야 합니다.
필터 장착 후에는 대역별 외형 차이 때문에 이 광학 흐름 방식의 적용 가능성을 다시 검증해야 합니다.
정량적인 다분광 분석에는 그대로 사용하지 마세요. 검증된 카메라 보정·동기화·대응 검증이 별도로 필요합니다.

`local_registration.jsonl`은 프레임별 왕복 일관성 통과 비율과 카메라별 오차 지표를 기록합니다.
이는 추정 품질 진단이며 정합 정확도의 정답값이 아닙니다.
사용자 제공 193프레임 영상에서는 손 주변 RGB 이중 윤곽이 시각적으로 줄었지만,
일관성 검사 통과 비율은 전체 픽셀 평균 약 32%에 그쳤습니다.
따라서 이 기능은 기본값으로 켜지 않으며, 시험 결과를 보고 선택하도록 제공합니다.
합성 결과와 검사 영상을 모두 확인해야 합니다. 처리 시간은 Pi에서 별도 확인하세요.

## 대상 지정 없는 시간축 떨림 완화 (권장)

현재 정합 정확도를 유지하면서 보정값의 시간상 떨림을 줄이기 위한 후처리입니다.
대상 영역이나 촬영 거리를 입력할 필요가 없습니다.

1. 프레임별 자동 정합을 체크합니다.
2. 기존 방식 — 매 프레임 ORB, 안정화 강도 강하게를 선택합니다.
3. 시간축 떨림 완화를 **31프레임**으로 선택합니다. 전체 흔들림 완화는 끕니다.
4. 합성 영상 저장을 누릅니다. 정합 분석과 평활화 영상 저장의 두 단계를 표시합니다.
5. 기존 `composite_dynamic.avi`와 새 `composite_dynamic_smooth.avi`를 비교합니다.

정합 결과의 영상 모서리 투영 좌표에서 5프레임 이웃의 중앙값·MAD로 일시적 이상치를
완화한 다음, 앞뒤 프레임에 대칭인 Gaussian 필터를 적용합니다.
기준 cam1의 변환은 유지합니다. 앞뒤 프레임을 함께 사용하므로 과거 프레임만 사용하는
필터의 일방적인 추종 지연은 줄지만, 급격한 거리 변화 주변의 정합 정확도는 낮아질 수 있습니다.
15/31/61프레임 중 선택하며 30fps 기준 대략 0.5/1/2초 범위입니다.
처음과 끝은 가장자리 값을 연장합니다. 짧은 영상에서도 동작합니다.

정합 설정과 실패 시 대체값 사용 방식은 유지됩니다. 실패 구간도 시간축 평활화의 영향을
받으므로 최종 사용 행렬은 `registration_smoothed.jsonl`, 평활화 전 결과는
`registration_dynamic.jsonl`에 별도로 저장합니다. 성공 횟수는 원래 정합 추정의 품질 검사
결과이며, 평활화가 실패 프레임을 새롭게 정합한 것으로 계산하지 않습니다.

원본 영상을 두 번 읽으며, 모든 원본 프레임을 메모리에 보관하지 않습니다.
보정 경로와 진단 기록은 프레임 수에 비례해 메모리를 사용하므로 긴 영상은 나누어 처리하세요.
전체 이동 보정을 별도로 켜면 그 보상량은 시간축 경로 필터 대상에 포함하지 않습니다.
이 기능은 실시간 모드가 아니며 물리적 카메라 흔들림, 시차, 촬영 시간 차이를 제거하지 않습니다.

사용자 제공 약 6.4초 영상의 193개 공통 프레임으로 검증했습니다.
강하게/ORB/31프레임 설정에서 보정 경로의 2차 차분 RMS는 약 98% 감소했고,
기존 경로 대비 제어점 이동량 중앙값은 약 0.4px였습니다.
이 수치는 변환 경로의 수치 지표이며, 시각적 떨림 감소율이나 모든 장면의 성능을 뜻하지 않습니다.

## 화면 전체 흔들림 완화

프레임별 정합은 RGB 윤곽의 상대 떨림을 줄이지만 기준 cam1의 흔들림 자체는 남습니다.
**화면 전체 흔들림 완화 (이동 보정)**을 켜면 cam1의 프레임 간 특징점을 추적하고
RANSAC 유효점의 중앙 이동량으로 전체 이동을 추정합니다. 누적 경로를 평활화하고
보상 이동을 합성 RGB 전체에 동일하게 적용합니다. 이 옵션은 프레임별 정합 모드에서 사용합니다.

결과는 `composite_dynamic_stabilized.avi`로 저장해 기존 동적 결과와 비교할 수 있습니다.
가장자리는 검게 표시되며 자동 확대·잘라내기를 하지 않습니다. 출력 크기는 640×480입니다.
이동 보상은 축별 ±50px로 제한합니다. 특징점 부족·급격한 움직임에서는 직전 보상값을
유지하고 `global_stabilization` 로그에 이유를 남깁니다. 추정 실패가 지속되면 효과가 없습니다.
이동 경로 평활화는 의도적인 팬에도 지연을 줄 수 있고, 회전·줌·롤링셔터·깊이별 시차를
보정하지 않습니다. 화면 대부분을 움직이는 물체가 차지하면 배경 대신 물체를 따라갈 수 있습니다.
진단 JSONL과 요약은 최근 동적 합성 실행의 결과로 덮어씁니다.

기본 비교는 **기존 방식 — 매 프레임 ORB** + **전체 흔들림 완화 끄기**로 진행하세요.
세션 선택 시 이 두 설정은 이전 저장값과 무관하게 기본값으로 초기화됩니다.
실험 기능은 하나씩 켜서 같은 짧은 영상으로 비교하세요.
특징점 추적은 `composite_dynamic_tracking.avi`, 여기에 전체 보정도 켜면
`composite_dynamic_tracking_stabilized.avi`로 저장합니다.
특징점 추적은 실제 장면에 따라 기존 방식보다 나빠질 수 있으므로 기본 사용하지 않습니다.
강하게 모드에서 오히려 RGB 윤곽이 뒤늦게 따라오면 균형/빠르게와 비교하세요.

## 시간 및 정렬의 한계

CSV는 프레임 수신 직후의 호스트 단조 시각이며 센서 노출 시각이 아닙니다.
합성은 공통 촬영 구간에서 cam1의 시각마다 가장 가까운 다른 카메라 프레임을 선택합니다.
이는 하드웨어 동기화를 보장하지 않으며 버퍼 지연·움직이는 물체의 오차가 남습니다.
AVI는 고정 프레임률 30으로 기록하므로 드롭 시 원본 재생 시간이 실제와 다를 수 있습니다.
합성에서는 CSV를 사용하지만 출력 역시 중앙 프레임 간격을 사용한 고정 프레임률입니다.
현재 정렬은 4점 원근 변환과 회전·배율·평행 이동을 지원합니다.
카메라별 렌즈 왜곡 보정(체커보드 캘리브레이션), 시간 오프셋 수동 보정,
실시간 합성, 저장 공간 감시, 자동 재연결은 후속 구현 대상입니다.
단일 평면 정렬로 서로 다른 거리의 물체에 생기는 시차를 모두 없앨 수는 없습니다.
